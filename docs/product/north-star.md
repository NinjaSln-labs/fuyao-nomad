# 北极星

## 一句话

**开源的、DDD 驱动的、可组队 Agent 团队框架——团队优先，挂到任意 harness，重量随情境调节。**

## 双名

| | 含义 |
|---|------|
| **扶摇** | 团队之魂：多角色逍遥协作，不缚于一地 |
| **Nomad** | 团队之能：规格可迁移，随处可栖 |

## 定位

```
AI 员工产品          →  一个很强的个体，封闭 runtime
多 agent 框架        →  编排 API，缺管理/质量/交付模式
Harness 内置 agent   →  单 agent 或浅层 subagent
─────────────────────────────────────────────────
扶摇 · Nomad         →  团队框架 + DDD + 编制规则 + 开源 builder 优先
                         薄适配 harness，不做 harness
```

## 能力域（8 域）

| 域 | 核心问题 |
|----|----------|
| 1. 团队编制 | 如何定义槽位、加减、边界？ |
| 2. 编排与协作 | 并行、争用、升级如何避免空转？ |
| 3. 管理与推进 | 谁盯进度、里程碑、阻塞？ |
| 4. 交付模式 | DDD 底座上如何调节轻-重流程重量？ |
| 5. 质量与验证 | 什么叫「做完」？如何防幻觉交付？ |
| 6. 治理与审计 | 哪些须人确认？留什么痕？ |
| 7. 研究与产品 | 竞品、PRD、发现如何进团队协议？ |
| 8. 可移植挂载 | 如何不重写 harness 而挂载团队？ |

## 受众 cascade

```
Agent Builder  →  小团队  →  单人
 可扩展            可协作      默认可用
```

## 成功标准（定稿 · 2026-08-22）

| 级别 | 标准 |
|------|------|
| **Builder** | 能发布「团队包」：槽位 + 技能 + 门禁 + `flow_weight`，他人可 fork 加减 |
| **小团队** | 共享 roster 与审计链，进度与 DoD 状态可交接 |
| **单人** | 默认团队跑通一类典型任务（如：调研→规格→实现） |
| **移植** | 同一团队包在 ≥2 个 harness 上挂载，核心 spec 不变 |

## 反指标（定稿）

| 反指标 | 说明 |
|--------|------|
| 默认 ceremony 过重 | 小任务也要求满配文档与百波审计 |
| 编制写死 | 用户必须接受「官方角色表」才能用 |
| Harness 渗透 | 团队核心逻辑依赖某一 IDE 私有 API |
| 单体回退 | 实际运行退化为单 agent + 长 prompt |

## 与竞品差异

> 详见 [竞品快照](../research/2026-08-22-agent-team-landscape.md)。

**差异化一句话（定稿）**  
开源 Agent 团队框架：DDD + 可加减编制规则 + **轻-重流程重量**；薄适配挂 harness，**不构建 harness，不卖单体 AI 员工**。

**编排不竞争** — CrewAI / Cursor / Devin 做强运行时；扶摇 定义**团队层** spec，可映射到各 runtime。

**最近邻** — BMAD（方法论+多角色）；扶摇 差异在 **DDD 必要 + 编制协议 + 跨 harness 团队包**。
