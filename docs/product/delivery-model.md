# 交付模式

## 公式

```
扶摇交付 = DDD（必要底座）
         + 青蚨使/Voyage 机制择优继承
         + 按情境调节轻-重流程重量
         − 不照搬不适用的 ceremony 与领域绑定
```

- **不以「敏捷」为主叙事** — 轻量手段按需用（spike、小步交付），主轴是 DDD + 情境化流程重量。
- **不是「全工程 vs 敏捷」二选一** — 同一底座上调节文档量、门禁强度、审计深度。

## 轻-重流程重量

流程重量是**从轻到重的连续调节**，不是固定的「三档」标签。

| 概念 | 说明 |
|------|------|
| **轻端** | spike、探索、只读调研、本地草稿 — 意图陈述 + 精简 DoD + 完成前验证 |
| **中间** | 常规模块、功能交付 — ADR（若硬约束）+ DDD 核心 + stage-spec + 追溯链 |
| **重端** | 高安全、多 agent 并行、长周期 — 完整追溯 + 分层审计 + 反指标 + 显式授权门 |
| **全流程** | 极重端：文档齐套、全追溯、全门禁（类似青蚨使/Voyage 满配）— **按需选用，非默认** |

**未来可扩展更细粒度**（实现时再定，不预设固定枚举），例如：

`轻 · 轻中 · 中 · 中重 · 重 · 全流程`

框架提供**调节机制与模板绑定**，不锁死档位数量；团队包声明当前任务的 `flow_weight` 即可。

默认位置由**任务风险、规模、时限**选择，非项目类型标签。

**联动对象**（同一 `flow_weight` 下对齐）

| 对象 | 随重量伸缩 |
|------|------------|
| DoD 模板 | 文档量、门禁项数量 |
| DDD 门 | 深度与轮次 |
| **验证 / 测试** | 跑通、证据、自动化测试深度 |
| **分层审计** | 设计 / 实现 / 代码质量评审深度 |
| 审计产物 | 治理留痕 + 质量审计结论 |
| **计划** | 轻端短计划 → 重端阶段与追溯（见 capability-model §3） |

## 继承 / 修正 / 丢弃表

与先行 Agent 交付实践的对照（研发代号：**Voyage**、**青蚨使** — 机制继承，非代码依赖）。编号 ①–㉓ 与发现阶段讨论一致。

### 继承（保留机制，形式可调）

| 机制 | 来源 | 扶摇 用法 |
|------|------|-----------|
| DDD 设计门 | Voyage M0-D | **必要**；轮次与深度随流程重量调节 |
| ADR 裁边界 | 青蚨使 | 硬约束写 ADR，不进 PRD 含糊处 |
| stage-spec 四段 | 青蚨使 | DoD / 验证 / 交付物 / 边界 → **模板** |
| 追溯链 | 两边 | 意图 → 领域 → 任务；轻端可缩形式 |
| HANDOFF 增量 | Voyage | 周期交接，引用权威路径不复制 spec |
| Port/Adapter + 契约测 | Voyage M6 | 对齐 harness **薄适配** |
| 反指标机制 | 两边 | 保留机制，指标由项目/团队包自定义 |
| 调研去权威化 | 青蚨使 research | 竞品快照不自动升格为 scope |
| 三层层文档审计 | 青蚨使 | 重端/全流程使用；轻端简化 |
| TDD 纪律 | 青蚨使 六核心 | 编码任务默认；非编码任务换验证方式 |

### 修正（机制对，默认量/范围不对）

| # | 原实践 | 修正方向 |
|---|--------|----------|
| ① | Voyage 157+ 波审计 | 审计**契约** + 旋转维度；深度随流程重量，不默认百波 |
| ② | 每波独立 `审计记录-第N波.md` | 可选产物格式；框架提供 schema，不强制体量 |
| ③ | M0-D 12 轮设计评审 | DDD 门保留；轮次上限与通过标准按重量调节 |
| ④ | 五类测试强制全覆盖 | 编码重面保留；非全面强制，按风险选类别 |
| ⑤ | 对抗矩阵每波追加 | 高风险面可选模块，非默认 |
| ⑥ | M0–M6 / S0–S5 固定编号 | 改为**可配置阶段模板**，不内置产品里程碑 |
| ⑦ | docs/ vs impl/ 产品二分 | 框架权威在**协议与模板**；用户项目自选文档结构 |
| ⑧ | PRD 为最高权威 | 通用「意图/任务」链；PRD 是重端的一种产物 |
| ⑨ | 16+ 文档齐套才编码 | 仅**重端/全流程**；其余显式缩减 |
| ⑩ | CLI→MCP→Web 切片顺序 | 用户自定表面顺序；框架不预设 |
| ⑮ | 每阶段人工「授权 S{n}」 | **分级门禁**：破坏性/远程/重端须授权；只读/本地轻端降级 |
| ⑯ | 无用户请求不 commit | 分级：自动 / 确认后 / 禁止 |
| ⑰ | DoD 默认全勾选才下一阶段 | 提供与流程重量绑定的 DoD 模板族（可扩展档位） |
| ⑱ | 100/100 审计才放行 | 重端/全流程门；中间 Major 清零；轻端自评 |

## 权威层级（框架级，草案）

```
编制协议 (composition-protocol)
    ↓
交付模式 (本文件) + flow_weight 选择
    ↓
团队包 (roster + 技能 + 门禁 + DoD 模板)
    ↓
任务/意图实例
    ↓
HANDOFF / 审计产物
```

冲突时向上 resolve。用户项目内的 PRD、领域模型等是**重端/全流程任务产物**，非框架全局权威。
